## 📋 About The Project

**NetPulse** is a real-time HTTP website monitoring tool built entirely in **Java** with a modern single-page dashboard. It was developed as the **end-semester project** for the course **CIC-301 (Computer Networks)**.

The tool demonstrates core computer-networking concepts in practice:

| Concept | How NetPulse Uses It |
|---|---|
| **DNS Resolution** | Performs live `InetAddress.getByName()` lookups and measures DNS resolution time in milliseconds |
| **HTTP Protocol** | Opens real `HttpURLConnection` GET requests, captures status codes (200, 301, 404, 503…), and measures round-trip latency |
| **IP Addressing** | Resolves and displays the server's IP address for every monitored target |
| **Client-Server Architecture** | Embedded Java HTTP server serves a dashboard UI and exposes a REST API consumed by the browser |
| **Concurrency & Scheduling** | Uses `ScheduledExecutorService` to poll multiple websites concurrently at configurable intervals |
| **Network Error Handling** | Detects and reports DNS failures, connection timeouts, SSL/TLS errors, and HTTP error codes |

---

## ✨ Features

- 🔍 **Real DNS Lookups** — Measures actual DNS resolution time (not cached) per target
- ⚡ **HTTP Health Checks** — Captures status codes and response latency via `HttpURLConnection`
- 📊 **Live Dashboard** — Single-page UI with auto-refreshing metrics every 5 seconds
- 📈 **System Summary Cards** — Total monitors, online/offline count, uptime %, average response time
- 🔴 **Incident Alerts** — Red banner appears when any website goes down or returns error codes
- ➕ **Add / Remove Monitors** — Add any URL with a custom polling interval directly from the UI
- 🔄 **Manual Refresh** — One-click button to force an immediate probe of all targets
- 🔎 **Search & Filter** — Filter the monitoring table by URL or IP address
- 📝 **Persistent Logging** — All metrics are appended to a CSV file; failures are logged separately
- 🚫 **Zero External Dependencies** — Pure Java 21 standard library; no Maven, Gradle, or third-party JARs

## 🚀 Getting Started

### Prerequisites

- **Java 21** (or later) — [Download OpenJDK](https://jdk.java.net/21/)
- A modern web browser (Chrome, Firefox, Edge, Safari)
- Active internet connection (to probe external websites)

Verify Java is installed:

```bash
java --version
```

Expected output: `openjdk 21.x.x` or higher.

### Clone the Repository

```bash
git clone <repository-url>
cd NetPulse/HttpWebsiteMonitor
```

### Build & Run

#### Option 1: Using the run script (Recommended)

```bash
chmod +x run.sh
./run.sh
```

This compiles all Java sources and starts the server on **port 8080**.

To use a custom port:

```bash
./run.sh 9090
```

To compile without running:

```bash
./run.sh build
```

#### Option 2: Manual commands

```bash
# Step 1: Compile
mkdir -p out
find src -name "*.java" | xargs javac -d out

# Step 2: Run
java -cp out Main
```

Or with a custom port:

```bash
java -cp out Main 9090
```

### Open the Dashboard

Once the server starts, you will see:

```
╔══════════════════════════════════════════════════════════╗
║   NetPulse Dashboard Server started                     ║
║   → http://localhost:8080                               ║
╚══════════════════════════════════════════════════════════╝
```

Open **http://localhost:8080** in your browser.

### Stop the Server

Press `Ctrl + C` in the terminal. The server shuts down gracefully.

## 📖 How to Use

### 1. View the Dashboard

On launch, NetPulse starts monitoring **4 default websites**:

| Target URL | Interval |
|---|---|
| `https://httpbin.org/status/200` | 10s |
| `https://api.github.com` | 15s |
| `https://httpbin.org/status/503` | 10s |
| `https://example.com` | 30s |

The dashboard displays a table with real-time metrics for each target:

- **Target URL** — The monitored website
- **IP Address** — Resolved IP from DNS lookup
- **Status** — `UP` (green) or `DOWN` (red)
- **DNS Lookup** — Time taken for DNS resolution (in ms)
- **HTTP Status** — Response status code (200, 301, 404, 503, etc.)
- **Response Time** — Total round-trip latency (in ms)
- **Last Checked** — Relative timestamp of the last probe

### 2. Add a New Monitor

1. Click the **"Add Monitor"** button (top-right)
2. Enter the website URL (e.g., `https://google.com`)
3. Set the check interval in seconds (default: 10s, minimum: 5s)
4. Click **"Start Monitoring"**

The new target will appear in the table and start being probed immediately.

### 3. Remove a Monitor

Click the 🗑️ trash icon on any row to stop monitoring that website.

### 4. Manual Refresh

Click the 🔄 refresh icon next to the search bar to force an immediate probe of all targets.

### 5. Search / Filter

Type in the search box to filter the table by URL or IP address.

### 6. Incident Alerts

When any website returns an HTTP error code (4xx/5xx) or is unreachable, a **red alert banner** appears at the top of the page listing the affected sites.

### 7. View Logs

After running, check the `data/` directory:

```bash
# View all historical metrics
cat data/monitoring_metrics.csv

# View failure/downtime events
cat data/failures.log
```

## 🔌 REST API Reference

The Java backend exposes a REST API that the frontend consumes. You can also use it directly with `curl`:

| Method | Endpoint | Description | Example |
|---|---|---|---|
| `GET` | `/` | Serves the dashboard HTML page | `curl http://localhost:8080/` |
| `GET` | `/api/metrics` | Returns all latest probe results as JSON | `curl http://localhost:8080/api/metrics` |
| `POST` | `/api/targets` | Adds a new monitoring target | `curl -X POST -H "Content-Type: application/json" -d '{"url":"https://google.com","interval":10}' http://localhost:8080/api/targets` |
| `DELETE` | `/api/targets?url=...` | Removes a monitoring target | `curl -X DELETE "http://localhost:8080/api/targets?url=https://google.com"` |
| `POST` | `/api/refresh` | Triggers immediate re-probe of all targets | `curl -X POST http://localhost:8080/api/refresh` |

### Sample API Response

```json
{
  "monitors": [
    {
      "url": "https://example.com",
      "ip": "93.184.216.34",
      "status": "UP",
      "dnsTime": 18,
      "statusCode": 200,
      "responseTime": 142,
      "timestamp": 1730665200000,
      "lastChecked": "Just now",
      "interval": 30
    }
  ]
}
```

## 🧠 How It Works (Architecture)

```
┌──────────────────────────────────────────────────────────────────┐
│                        Browser (Client)                          │
│    ┌──────────────────────────────────────────────────────────┐  │
│    │   index.html — Tailwind CSS Dashboard                    │  │
│    │   • fetch('/api/metrics') every 5 seconds                │  │
│    │   • POST/DELETE to /api/targets for add/remove           │  │
│    └───────────────────────┬──────────────────────────────────┘  │
└────────────────────────────┼─────────────────────────────────────┘
                             │ HTTP
┌────────────────────────────┼─────────────────────────────────────┐
│                   Java Backend (Server)                           │
│                            │                                     │
│    ┌───────────────────────▼──────────────────────────────────┐  │
│    │   DashboardServer (com.sun.net.httpserver.HttpServer)     │  │
│    │   • Serves index.html on GET /                           │  │
│    │   • REST API: /api/metrics, /api/targets, /api/refresh   │  │
│    └───────────────────────┬──────────────────────────────────┘  │
│                            │                                     │
│    ┌───────────────────────▼──────────────────────────────────┐  │
│    │   MonitorScheduler (ScheduledExecutorService)             │  │
│    │   • Runs each target on its own periodic schedule         │  │
│    │   • Multithreaded: one thread per available CPU core      │  │
│    └───────────────────────┬──────────────────────────────────┘  │
│                            │                                     │
│    ┌───────────────────────▼──────────────────────────────────┐  │
│    │   NetworkProber                                           │  │
│    │   • Step 1: InetAddress.getByName() → DNS time + IP      │  │
│    │   • Step 2: HttpURLConnection.GET → status code + latency│  │
│    └───────────────────────┬──────────────────────────────────┘  │
│                            │                                     │
│    ┌───────────────────────▼──────────────────────────────────┐  │
│    │   MetricsStore                                            │  │
│    │   • ConcurrentHashMap for latest results                  │  │
│    │   • Ring buffer (100 entries/URL) for history             │  │
│    │   • CSV writer → data/monitoring_metrics.csv              │  │
│    │   • Failure logger → data/failures.log                   │  │
│    └──────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```
